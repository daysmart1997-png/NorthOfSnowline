# 第一章生存深度、动物与人物界面

2026-09-09 · 设计提案，不是实装清单。

本轮核对现有规则并制作两张界面概念图。没有修改玩法数值、出生点、存档或运行界面；动物、武器、疾病、换装均仍待实现。上一轮已完成内容见 [18](18_LOST_CONTACT_AND_WORLD_REFINEMENT.md)，接续状态见 [PROGRESS](PROGRESS.md)。保留 [WORLD_BIBLE](WORLD_BIBLE.md) 中寻找周岑、区域失联、只有信息跨越时间的约束。

## 1. 为什么现在可以不吃不喝通关

源码依据：`scripts/expedition.gd` 的初始状态、tick、temperature_rate、use_item；`scripts/day_cycle.gd` 的时钟；`scripts/main.gd` 的出生位置；`scripts/world_expansion.gd` 的维修站位置。

| 规则 | 当前实际值 | 影响 |
|---|---|---|
| 初始饱食 / 水分 | 85 / 80 | 出门余量很充足 |
| 普通行动每秒消耗 | 饱食 0.027、水分 0.043 | 连续 10 分钟后约 68.8 / 54.2 |
| 饥渴后果 | 饱食 ≤15 才降低体力恢复；食水归零才扣健康 | 大部分第一章没有可感知的饥渴压力 |
| 归零所需时间 | 饱食约 52.5 分钟、水分约 31.0 分钟 | 理论值；未计食物、冲刺、休息、死亡与暂停 |
| 起始物资 | 口粮 2、饮用水 1、木柴 2 | 还有两次 +32 饱食、一次 +40 水分 |
| 小屋到维修站 | 出生 z=20.5，站点 z=-170 | 直线往返 381 米，按 1.65 米/秒约 3.85 分钟 |
| 世界时间 | 现实活动 24 分钟 = 游戏 24 小时 | 新行动耗时必须与天气、火炉、睡眠共用时钟 |
| 绷带 | 两份布制作，直接 +22 健康 | 不需要先判断伤情，实际是通用回血物品 |

以上是静态公式与理想直线路线估算，**不是首次玩家完整通关测量**。实际路线有地形、碰撞、低温、冲刺、探索与阅读。10 分钟数值只隔离食水，不表示玩家在户外能无条件安全站 10 分钟。

结论：先补充有意义的停留、返程准备和状态后果，不能只加倍饥渴速度。经验玩家理解规则后应能更快完成，不强制用“吃过一次”“杀过一头鹿”解锁剧情。

同时记录一个现存规则不一致：`tick()` 中“归途”回血只判断在庇护所内，没有核对燃火/实际温暖，而描述写在温暖庇护所生效。接入健康规则时统一取样，不让音乐绕过伤病处理。本轮未修改。

## 2. 第一章：获得小屋，再让它真正能住

建议首次游玩目标 **25–40 分钟墙钟时间**，包含阅读与比较；不是已经达到的时长。预计活动模拟约 12–18 分钟，休息/制作另按世界分钟推进。当前上午九点开局自然走向夜晚；不要求固定等到某个时间才能完成。

小屋应当早出现，成为想回去的地方。它初期避风但冰冷，无线电失灵，食水和衣物准备不足。找到房子不等于获得永久安全。

| 段落 | 首次体验目标 | 需要玩家决定的事 | 叙事回报 |
|---|---|---|---|
| 封路现场 → 七号 | 2–4 分钟 | 从邮递车取应急物资，辨认电线杆/路标；不强制受伤 | 山崩与退路受阻可亲眼确认 |
| 第一次暖身 | 4–6 分钟 | 用有限木柴添火、取水、烘干还是保留燃料 | 值守簿解释周岑与失联 |
| 林道 / 冻湖边缘 | 7–11 分钟 | 安全绕行，或经过狼活动区节省时间；中途折返可行 | 足迹、咬痕、废弃营地提供信息 |
| 北岭维修站 | 4–6 分钟 | 找模块并进行短修理；搜衣柜、取工具、补给都需时间 | 保留原交接单和三类证据 |
| 返程 → 呼叫 | 6–10 分钟 | 带肉还是零件，借营地回暖还是继续走 | 正常联系谷口，随后可选旧频道 |

这些区间合计约 23–37 分钟，仅用于排布内容；用首次试玩验证 25–40 分钟目标，不能直接把表格当通关数据。

先用现有封路、邮递车、小屋、营地、冻湖、维修站组织路线，不先扩大地图。将出生点移到室外时，必须一起调整开场“昨夜退回小屋”的时间表述、镜头、第一条目标与存档恢复；旧存档不强制迁移出生点或重播教学。

维修不设计成“等进度条三分钟”：让玩家检查电源、判断模块、选择补给与离开时机；每步提供可见信息或物品收益。留安全绕行，暴雪给提前预兆，不在玩家脚下突然刷狼。原 six-branch 正常通话、可选尾声、无磁带通关都保留。

## 3. 动物：先让玩家看懂行为

以下为项目的游戏规则，不是现实野生动物行为指南。

| 动物 | 行为与意义 | 第一章安排 |
|---|---|---|
| 鹿 | 警觉、抬头、逃离；提供足迹与食物来源，不追杀玩家 | 一处林间活动区；先可发现既有鹿尸，狩猎不是必修 |
| 狼 | 观察、靠近、低吼警告，满足条件才扑击；可以失去目标 | 一处可绕开的活动区，初版最多两只同时参与 |
| 熊 | 地盘与护食压力、明显警告、短距离冲锋，高风险 | 后续区域；第一章可留足迹，不安排必经熊战 |

**感知分开计算**：视野检查距离/朝向/遮挡；脚步产生有位置与强度的声音事件；新鲜肉形成受风向影响的有限气味范围。每个通道贡献 0–1 警觉值，未感知时衰减。不会全图读取玩家坐标，也不会隔墙看到背包里的肉。

初始调参种子：狼近距离视觉范围约 12 米，外围观察 20 米；静走声音半径约 4 米、冲刺约 10 米，表面与天气修正。必须用当前正交镜头检验警告能否被看见；不是最终平衡值。风雪降低视觉和听觉范围，气味按风向扇区计算，不能简单让大风提升全向追踪。

状态机：游荡 → 察觉 → 观察/警告 → 追踪 → 攻击 → 脱离/撤退。警觉跨 0.35 进入察觉、跨 0.70 并持续确认进入警告；低于较低阈值再退出，避免反复闪状态。狼只在持续接近、受击或警告后仍进入近距条件时尝试攻击。

一次扑击：约 0.7 秒前摇、单次命中窗口、约 1 秒恢复；每个攻击 ID 只能伤害一次，不能每帧扣血。初始伤害候选 12–18 / 100，衣物先吸收部分并损耐久；少量可解释伤情由实际命中部位决定。面向/距离/遮挡仍须在命中时复核。镜头外攻击也必须有方位提示和声音预兆。

遮挡后只追到最后已知点，搜索一段时间后回活动区；追击有距离与时间上限。确认关闭的室内不可进入，不能隔墙攻击或堵住唯一出口。安全路线不能因随机刷新完全消失。急救、地图、暂停菜单打开时，动物与生存共用暂停状态。

## 4. 狩猎、武器和取肉闭环

推荐接入顺序：**发现鹿尸 → 用小刀分批取肉 → 带回烹饪 → 追踪活鹿 → 弓箭 → 稀缺猎枪**。先验证食物收益与返程代价，再增加瞄准/弹道；第一章可不开枪完成。

- 小刀来自维修站工具柜，不由废铁徒手瞬间变出来。选择取 0.5 千克、1 千克等份量；界面预览用时、重量、气温与工具损耗。分段结算，取消只保留已完成段，避免复制或整批吞物资。
- 生肉占重量，有新鲜度和气味代价；烹饪需炉火、时间与可用燃料。吃生肉的风险在确认前说明；不先做一套微生物模拟。
- 按现有比例，10 个世界分钟等于 10 秒活动时间；耗时行为采用连续短段推进，允许危险中取消，不把一小时剥皮做成强制现实一小时等待。菜单比较暂停，确认执行才推进时间。
- 初版尸体只产肉，后续再加皮与筋腱、晾晒架、皮革衣物；无狩猎经验的玩家仍有可靠口粮来源。
- 弓需要一套固定视角瞄准、蓄力、散布、箭体碰撞与回收，图上有弓不等于系统完成。弓来自储藏/修复，制作成熟后再开放。
- 猎枪后续从有出处的护林设施获得；固定视角下瞄准时转角色，不改越肩镜头。少弹药、较高噪声和负重，有装填/射击前后摇。按游戏规则制造远近可辨的声音事件，不在开枪后凭空召唤狼群。
- 动物模型、待机/走跑/警觉/受击/死亡动作和碰撞要一起验收。不要让单个人形动作重定向冒充四足动物动画。

## 5. 健康：先有原因和应对，再有更多状态

保留 health 一个总体健康值，叠加有部位、严重度、来源和恢复条件的 condition 记录。第一批做**湿衣、受寒、扭伤、开放伤口**；食物不适随取肉烹饪加入。感染/发热、长期病程留后续，不用“走进雪里立刻感冒”凑系统。

| 状态 | 游戏触发 | 可读后果 | 对应行动 |
|---|---|---|---|
| 湿衣 / 受寒 | 深雪浸湿、持续暴露与衣物保护不足 | 局部保暖下降、发抖与恢复变慢 | 避风、换干衣、炉边烘干 |
| 脚踝扭伤 | 急降坡/跌落/超负重等明确事件，不是普通走路随机罚款 | 冲刺受限，标出左右部位 | 支撑处理、减负和安全休息 |
| 开放伤口 | 动物实际命中或明确环境伤害 | 可见出血、衣物破损 | 对应部位包扎，之后恢复；不直接通用 +22 健康 |
| 食物不适 | 明示风险的生食/变质食物 | 饮水负担与精力恢复受影响 | 安全食水、休息；药物规则单独配置 |

药品必须区分止血/缓解/恢复；小屋与维修站药箱提供成品药物，草药只保留游戏中的暖身饮品，不设“草药 + 废铁 = 万能抗生素”。布料配方可以产出游戏用基础包扎物，但不同伤情是否适用必须在物品信息写清，不把它写成现实医疗说明。

咳嗽作为有原因的反馈：例如受烟雾刺激或后续呼吸道状态；跑后的喘息继续由体力与恢复状态驱动，受寒主要用发抖和呼气。触发带间隔与随机错开，不能每帧重复或十秒循环一次；剧情关键语音期间降低频率，配字幕/状态图标，留强度设置。只有已发生的游戏声音事件才进入动物听觉。

建议首轮试验参数，而非直接写死上线：新局饱食 60、水分 55；普通行动保留 0.027 / 0.043 基础消耗；低于 35 出现温和预警、低于 20 渐进降低恢复，归零再损健康。10 分钟不补给约 43.8 / 29.2，20 分钟约 27.6 / 3.4。冲刺与耗时行为会更早消耗，因此必须有稳定补给、充分警告和可撤退路线。

这个候选说明延长有效活动后无需暴增消耗。开局较低状态需剧情说明为封路与出车消耗，不能把旧玩家已有数值降到候选值。吃喝应改善远行余量与恢复，不设不吃一餐就不能阅读任务的硬门槛。

## 6. 衣着和人物页必须是一套交互

先做帽、外套、手套、裤、靴五个服装部位，加一个背包装备位。袜子、内衬先作为升级材料，不增加隐藏层叠衣柜。每件衣物记录独立实例 ID、保暖、挡风、湿度、完好度、重量；背包额外记录容量。定义与实例分开，两个同名外套不能共享同一湿度。

简化保暖候选：各部位保暖 × 完好系数 × 湿度修正，再汇总；五部位贡献有上限，背包不当外套叠保暖。挡风只削减室外风冷项，屋内湿衣仍需烘干。具体权重通过裸装/基础装/修补装/湿装四组对照决定，不对外把这个抽象值称作精确人体体温。

获取形成地点记忆：小屋衣钩有旧手套，邮递车包裹有布料或袜衬，维修站衣柜有较重耐风外套，猎人营地有修补工具。探索所得旧衣通常需要修补/烘干；制作先从修补、加衬开始，后续加入动物皮衣物，不能两块布直接做顶级羽绒服。

人物页核心流程：**点击脚部 → 看到是湿靴还是扭伤 → 查看原因和后果 → 选择可用行动 → 预览成本与结果 → 确认 → 实际状态与外观同步。**

- 上方只保留人物 / 行囊 / 手记。人物页含衣着、身体两种视图；不把装备状态和疾病塞进同一个不分层列表。
- 角色用现有模型的独立预览实例，支持拖动旋转。衣着视图点击装备槽；身体视图点击头、躯干、左右手、左右腿查看当前异常，不新增六条常驻生命条。
- 左侧人物、右侧一张详情纸页；选物后显示当前 vs 替换后的保暖/负重/湿度变化。无材料/无火时显示具体原因与获取路径，不能只灰掉按钮。
- 默认点击选择、明确按钮执行；双击、拖拽不能作为唯一入口。键盘焦点顺序与手柄导航可达；Esc 先退出子详情，再关闭整页。
- 切换衣服为原子事务：检查容量与合法槽位后执行，旧衣回包；无法存放先说明，不静默掉地或复制。身体治疗也由规则层结算，不由页面扣一次材料、另一个系统再扣一次。
- 开包在约 0.25 秒内掀开帆布与纸页；常用操作不强制看长卷轴动画，减弱动态设置改为短淡入。查看暂停；烘干/修补等计时动作确认后进入可取消进度。
- 只让装备的独立网格/材质在角色上变化。当前 ranger_refined 导出为合并蒙皮网格，真正换装需在 Blender 拆分相关服装、保留权重、导出并逐动作检查穿模；UI 里的彩图不能替代这项资产工作。

美术语言沿用冷蓝帆布、暖灰纸页、墨迹、克制赭黄；装备页像打开行装，剧情页像阅读现场记录。环境保持露出，UI 不占满四角。概念由内置 image_gen 生成；工具未返回可核验的底层型号，不把图声明为指定 Sunburst/Flare 的输出。

OpenAI 官方在 2026-09-08 宣布 Images 2.5，包括 Codex 可用性与 API 的 Flare / Sunburst。已核对[发布页](https://openai.com/index/introducing-chatgpt-images-2-5/)和 [Sunburst 模型页](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)。当前工具不提供 model 参数，因此无法按名字强选其中一款；没有转用付费 API 或要求密钥。

图稿检查：角色识别、纸页层级与短文可读性成立。人物图出现额外装饰文字/英文、袜衬被画入替换区、两处重复说明；正式版删除这些内容并将袜衬移入升级材料。纸页破损/帆布噪声应减弱，人物靴子仍必须按实际足长，不能照图重新放大。剧情图中的收音机插画只作来源提示，不变成室外的新交互机器；暖窗不能代表无燃料也可回血。

**图稿不是功能截图，也不是新场景资产已做完。** 正式版本只把纸/布底纹、边缘和独立插画导入为图像；正文、标题、数值、按钮、焦点与进度保留原生 Godot UI。人物采用 3D 预览。图稿背景细节不视为当前可玩的建筑或承诺的模型精度。

文字先按 1280×720 设计，正文 18–22 逻辑像素、行高约 1.45、约 44 像素操作高度；标题可用现有衬线候选，正文清晰无衬线。支持原有 85–130% 字体偏好；长页滚动，中文断行/焦点不溢出。优先保障 Windows/Mac 字体候选与现有多分支长文，不直接把生成中文烘焙进正式按钮。

## 8. 实施依赖与验收

| 批次 | 交付 | 通过条件 |
|---|---|---|
| A 生存与人物页 | 服装实例/湿度、前四类状态、身体与衣着页、火边行动、剧情页皮肤 | 因果可见；装备与背包不复制；暂停不消耗；无火不能烘干；旧档保留 |
