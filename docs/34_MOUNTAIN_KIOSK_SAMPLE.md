# 山口与岗亭可玩样板

本批实现 33 号方案的首个样板，不表示四栋建筑全部完成，也不替代玩家试玩。原南侧路线、六类实物与主线流程继续沿用。

## 玩家体验

新旅程从山口走出，随身口粮为零，初始饱食值 35，仍有一份饮水和一根木柴。低处雪道通向电杆和岗亭轮廓；绕向背风岩脚可多拾取一根有限木柴。岗亭无炉无床，桌面物资可翻找、按件领取并使用。随后查看路线纸，寻找临时木屋和长期据点，衔接原求援主线。

开场三个镜头留在山口，文字与任务不再描述眼前发生雪崩。离开山口后才出现岗亭方向提示，进入发现后提示寻找首份食物，拿到食物后提示看路线纸。房屋无命名牌。旧存档读取不会清空原口粮，也不强制重走新开场。

## 实现

- `terrain_profile.gd` 在 Z>115 的南侧加入山肩和低谷，视觉雪面与碰撞仍使用同一地形采样。旧北侧玩法区保持原高度公式。
- `mountain_pass.gd` 替代世界实例中的旧路障开场，实例化 Blender 山体和岩组、放置电杆与有限木柴。旧 `south_pass.gd` 保留，没有删除历史源。
- `arrival_catalog.gd` 为岗亭指定独立模型路径与门檐柱/工具柜外部碰撞，`arrival_world.gd` 按目录加载。桌面供给、纸条与房间范围继续使用现有数据。
- 岗亭独立灰绿板墙、长单坡铁檐、窗洞/木框、侧工具柜和薄覆雪；三类材质有颜色、粗糙度和法线贴图，导入后保留，避免旧木材 shader 覆盖。山石另用坡向覆雪 shader。制作流程与来源见 `source_art/mountain_pass/README.md`。
- `Expedition` 仍是物资状态来源。新游戏只调整初始口粮，`supply_taken` 与 `collected` 保存领取；schema 仍为 7。

## 验证入口与限制

`tools/run_checks.py` 新增 mountain 检查，累计 24 组。专项包含实际输入通行、开场暂停/跳过、导入材质、首次翻找/食用、室内剖切、有限木柴和存读档。`mountain_preview.tscn` 是静态实际渲染检查，不能当作玩家操作证据；`mountain_check.tscn` 才包含输入路线。

全章路径使用 `station_playtest.tscn`，必须 `--fixed-fps 30`（该历史工具的观察帧数按 30 FPS 计算），用户参数为 `--isolated-settings --arrival-route --mountain-route --flow-content`，林道返程加 `--sheltered-return`。所有输出在 `artifacts/mountain-pass`；没有录像或读写玩家存档。

实际通过情况以 PROGRESS 顶部最终记录为准。当前山石仍为风格化样板，轮廓、地形过渡与远景层次可继续细化；另三栋建筑尚未套用此材质/建模流程。没有新增手部 IK 或角色语音，原物资短音未重制；Windows、发布包、性能专项与陌生玩家可发现性仍待验证。
